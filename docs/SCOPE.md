# Agreed project scope

On 18 October 2026, the project owner confirmed that the requirements can be relaxed and requested a Python backend with practical improvements based on the brief.

The implementation therefore prioritises a coherent savings workflow over contract or transaction counts:

- Python/FastAPI backend, persistent SQLite storage and existing-account migration.
- Customer, Administrator and invited read-only Auditor roles.
- MetaMask wallet proof, principal deposits/withdrawals, reserve funding and interest claims.
- One focused Solidity savings contract and four genuine business transaction types.
- Recorded-activity charts, paginated/filterable history, CSV export and account audit trail.
- A fee preview and explicit user confirmation before wallet signing.
- Tested Docker packaging and Render configuration, plus accurate report/manual/slides.

The original three-contract and ten-transaction counts remain visible for comparison but are not treated as automatic reasons to add unrelated features. Public deployment, actual MetaMask acceptance, authentic GitHub history, stakeholder research and performed demo evidence are still not claimed without being completed. Testnet only; no real-money readiness claim.
